# Pulse Rewards 架构与模块边界

按职责组织业务能力，使用纯函数处理金额与规则，通过应用服务编排异步解析、会话事务和外部适配器。UI 不导入 PDF 库或汇率请求实现。当前为上传与返现融合的个人单页，不包含账单页、设置、路由或持久化模块。

## 依赖规则

```text
pages / components → application / store → domain
                                      ↘ ports ← adapters (PDF / FX / vault)
```

业务数据流为 PDF 文本提取 → 原始行解析 → 规范化 → 自动分类 / 核对 / 奖励计算 → 会话提交 → 页面查询。异步任务由应用服务调用端口，纯领域模块不依赖 UI、浏览器 API、网络或持久化。

原稿将分类同时列在规范层与规则层。实现统一为：规范化还原账务方向、日期、金额、卡片及来源；业务分类和奖励资格由领域识别模块处理。解析层不计算余额或奖励。

## 不变量

- 账务金额用整数最小货币单位，奖励用整数 microRC（1 RC = 1,000,000 microRC）。输入超出安全整数或格式无效时给出可追溯错误。
- 奖励先在完整会话中按交易日确定性排序计算，再做筛选和汇总；同日交易使用稳定来源顺序，避免导入顺序改变截断结果。
- 使用交易日切分历史周期；最新规则的年度 / 半年结构回套历史，不使用当前日期覆盖交易年份。
- 退款、还款、费用等仍参与结欠核对；退款不改变奖励和封顶池。
- 所有卡保留单独收益，只有 confirmed 的额度归属证据可共享池。unknown 不能靠姓名相似或卡尾号猜测合并。
- 文件指纹去重在导入层；跨文件交易去重需相同银行唯一引用及匹配关键字段。没有唯一引用的同额同日消费保留。
- 批次仅在结束时提交。取消及过期异步回调不允许更新此前会话。
- 缺少汇率以 null / unavailable 表达，与零奖励区分。参考汇率可以用于缺少银行港币等值时的赏世界封顶估算；刷新可能改变附加 RC，但不能作为商户地区或支付方式的资格证据。
- 文案使用代码标识，领域函数不返回面向用户的中文或英文句子。

## 测试与安全边界

Vitest 保持 Node 单元测试，不引入组件快照或复刻实现的测试。重点验证跨年、边界金额、共享封顶、退款不释放、缺失余额、唯一证据去重、CSV 公式防护、批次取消和密文恢复等核心函数。

浏览器交互、键盘、页面断点和本地请求检查通过实际运行验收。真实原件和解锁密码留在仓库之外，测试报告只保留匿名编号、汇总计数和状态；不提交原文交易、个人姓名、卡号、文件指纹或原件截图。

## PDF 提取边界

- `ports/pdf.ts` 只定义文件输入、坐标文本页、读取选项、资源释放与稳定错误代码；应用批次控制器可注入其他提取实现。
- `adapters/pdf` 使用固定版本 PDF.js，通过显式 Worker 端口处理 PDF，无法启动时明确失败，不退回主线程假 Worker。引擎按需加载，Worker、字体、CMap 和解码资源随构建提供。
- 支持资源只按构建时白名单映射读取，不把结单内容拼进请求 URL。PDF 以本地字节输入，不启用表单脚本或 XFA，也不跟随结单中的链接。
- 坐标统一为页面左上角坐标系；纯文本布局函数按基线与横坐标重排行，保留原片段、行号和合并边界，后续交易模板不依赖 PDF.js 对象。
- 应用控制器独占尚未提交的批次，指纹、文件引用和已打开文档不进入公开 UI 状态；密码仅在单次解锁调用中传递，不进状态、日志或存储。
- 提取成功时立即释放 PDF 文档、Worker 和原文件引用，只保留内存文本页供模板解析；移除、取消和清除会话删除其临时文本。异步结果需同时匹配批次、条目引用和未取消信号，过期结果只能释放自身资源。
- 文本提取状态不能写入返现会话；S3.2 完成模板及统一入账后，才能把它作为真实导入使用。不提供原 PDF / 文本预览页面或持久保存。

PDF API 依据：[官方示例](https://mozilla.github.io/pdf.js/examples/)、[官方 API 定义](https://mozilla.github.io/pdf.js/api/draft/api.js.html)。

## UI 约束

- 使用 shadcn `b4hZZS5Uu` preset：Mira、Red / Neutral、Inter、Remix Icon、无圆角。通过项目已安装的 `shadcn/preset` 解码核实。
- 通用交互只使用 `components/ui` 中的官方组件；业务层只组合组件与 Tailwind 布局工具类，不维护自定义 CSS、行内视觉样式或额外主题。
- UI 源码来自 shadcn 官方 Base UI registry 与 Mira 样式，仅展开官方样式占位符、适配路径别名和图标；版权文本保留在 docs/licenses/shadcn-ui.txt。
- `CashbackPage` 负责单页编排；`LocalPdfImport` 只负责输入与批次状态；`RewardBreakdown` 与 `RewardRules` 分别负责收益解释和只读来源。数据计算仍由应用查询接口调用纯领域函数。
- `application/session/reward-details.ts` 汇总卡片来源、覆盖期、消费笔数和分币种金额；逐档计奖金额直接读取引擎的封顶结果，不在 UI 重写资格或封顶逻辑。未知金额按币种传播 null，保留其他档已知结果；去重交易的多份来源不重复累计消费。
- `reward-quality.ts` 统计来源核对与交易警告，`reward-pools.ts` 仅为视图补全已观察周期的未使用额度，不修改计算引擎的活动池。全局质量直接来自完整会话，不对各卡重复引用的来源核对再求和。
- `RewardCaps`、`RewardReasons`、`RewardQuality` 只负责展示；已知奖励、原因计数和资格均来自应用查询，组件不重新计算。
- `ports/fx.ts` 定义只含百万分率与参考日期的报价端口；`adapters/fx` 校验固定来源的响应并处理超时，不能接收结单参数。`application/fx` 管理自动获取、过期、旧值回退与取消；UI 只读快照并触发刷新。
- `SessionState.revision` 是数据版本。`setFx` 发布新快照但不推进该版本；批次提交读取当时最新的 FX。清空 / 示例切换推进数据版本，同时 FX 控制器取消自身请求；两个异步流程分别防止迟到写回。
- `application/session/validate.ts` 复用同一查询预检可计算性；解析后隔离单份异常，合并 / FX 发布前验证最终完整快照。安全整数的逐笔输入不被误认为安全的奖励或合计，失败不能先写入再等待 React 抛错。
- 官方 Accordion 增加与本 preset Button 一致的可见键盘焦点修复，仅使用既有 token 的工具类；不新增业务 CSS。
- `ports/statements.ts` 定义文本页到结构化结单的异步端口，`adapters/statements` 仅准备本机不透明标识后调用纯模板；`application/import/merge.ts` 先完整合并 / 校验 / 去重，`commit.ts` 通过版本检查后仅写会话一次。
- 批次控制器保管尚未提交的解析数据；读取 / 识别 / 待解锁结束前不发布业务会话。成功提交后清理临时数据，关闭状态列表不撤销已提交消费；取消和过期回调不触发提交。
