# Pulse Rewards 架构与模块边界

按职责组织业务能力，使用纯函数处理金额与规则，通过应用服务编排异步解析、会话事务和外部适配器。UI 不导入 PDF 库、存储底座或汇率请求实现。

## 依赖规则

```text
pages / components → application / store → domain
                                      ↘ ports ← adapters (PDF / FX / vault)
```

业务数据流为 PDF 文本提取 → 原始行解析 → 规范化 → 自动分类 / 核对 / 奖励计算 → 会话提交 → 页面查询。异步任务由应用服务调用端口，纯领域模块不依赖 UI、浏览器 API、网络或持久化。

原稿将分类同时列在规范层与规则层。实现统一为：规范化还原账务方向、日期、金额、卡片及来源；业务分类和奖励资格由领域识别模块处理。解析层不计算余额或奖励。

| src/domain/rewards | 只读官方规则、逐笔计算、共享池、周期封顶 | 筛选状态、持久化、网络 |
| src/domain/queries | 筛选、排序、搜索、聚合、导出数据选择 | PDF、网络 |
| src/application | 批次、密码生命周期、取消、导入提交、会话用例 | 具体组件 |
| src/ports | PDF、汇率、加密档等接口 | 具体库 |
| src/adapters | Worker PDF、固定白名单 FX、本地 vault 等端口实现 | 页面组件 |
| src/store | 可订阅内存会话与事务状态、页面查询入口 | 业务规则重写 |

目录随功能创建，不先建立空文件或空壳服务。

## 不变量

- 账务金额用整数最小货币单位，奖励用整数 microRC（1 RC = 1,000,000 microRC）。输入超出安全整数或格式无效时给出可追溯错误。
- 奖励先在完整会话中按交易日确定性排序计算，再做筛选和汇总；同日交易使用稳定来源顺序，避免导入顺序改变截断结果。
- 使用交易日切分历史周期；最新规则的年度 / 半年结构回套历史，不使用当前日期覆盖交易年份。
- 退款、还款、费用等仍参与结欠核对；退款不改变奖励和封顶池。
- 所有卡保留单独收益，只有 confirmed 的额度归属证据可共享池。unknown 不能靠姓名相似或卡尾号猜测合并。
- 文件指纹去重在导入层；跨文件交易去重需相同银行唯一引用及匹配关键字段。没有唯一引用的同额同日消费保留。
- 批次仅在结束时提交。取消及过期异步回调不允许更新此前会话。
- 缺少汇率以 null / unavailable 表达，与零奖励区分。参考汇率可以用于缺少银行港币等值时的赏世界封顶估算；刷新可能改变附加 RC，但不能作为商户地区或支付方式的资格证据。
- 文案使用代码标识，领域函数不返回面向用户的中文或英文句子。

## 测试与安全边界

Vitest 保持 Node 单元测试，不引入组件快照或复刻实现的测试。重点验证跨年、边界金额、共享封顶、退款不释放、缺失余额、唯一证据去重、CSV 公式防护、批次取消和密文恢复等核心函数。

浏览器交互、键盘、页面断点和本地请求检查通过实际运行验收。真实原件和解锁密码留在仓库之外，测试报告只保留匿名编号、汇总计数和状态；不提交原文交易、个人姓名、卡号、文件指纹或原件截图。
